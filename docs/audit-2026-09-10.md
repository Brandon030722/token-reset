# token重置 全链路审计 · 2026-09-10

审计版本：0.6.0 / rules-v2。范围包括 RSS/Atom 采集、英语规则、事件归并、SQLite、前端数据协议、macOS helper/系统通知、订阅入口、Brevo/MailerLite 发送及 Actions。Windows 仅静态检查，没有 Windows 实机测试；云端尚未部署。

## 最重要的结论

旧版“85%”是关键词分支返回的常量，不是概率模型计算结果，也没有历史样本支持“80% 门槛有效”。此前百分号的呈现具有误导性。本次统一改为 **信号评分 /100**，明确“不是发生概率、尚无历史命中率”。保留 80 分作为用户选定的提醒策略，而不是声称 80% 准确率。

高分只代表检测到明确措辞，不意味着独立核验了发帖者身份、事件一定发生或每个用户都能收到重置。它更接近公告线索监控器；当前不能称为经过验证的预测系统。

## 当前提醒条件

85 分：同一句满足 Codex 重置、we will/we'll 等明确承诺、全体用户或全体付费用户、today/tonight/tomorrow/24/48 hours 时间词；不能命中排除条件。低分 45/55/60 是线索等级，无统计距离意义。上下文补偿和完成/撤回不构成未来广泛高分。旧 24h 数字仅为协议兼容保留，不再提供 24/48 概率切换。

发信还要求：live、rules-v2、最近成功采集和评分生成不超过一小时、未到窗口截止、来源链接规范、证据完整、当前原文确为承诺、无完成或撤回、事件状态一致、非待核对事件、未被发送账本领取。首次历史事件不补发。Brevo 再检查专用名单、确认订阅配置、发件地址、人数上限和服务返回额度；实际 campaign 收件名单必须与配置完全一致。

本机通知有独立领取/确认账本。邮箱投递失败不能改变本机提醒的资格；操作系统接收通知也不等于用户看到横幅。

## 仍存在的限制与遗漏

1. **没有统计有效性证明。** 本次修复不能把 80 分变成 80% 概率。极低频事件尤其容易缺少独立样本。
2. **镜像漏帖仍是最大外部瓶颈。** 默认只有一个 FxEmbed 来源；“没有新事件”只能表示已读取的内容没有命中。HTTP 成功与缓存新鲜不证明时间线完整，多个镜像也可能共享上游。没有绕过访问控制或登录。
3. **自然语言仍会误判/漏判。** 上下文省略 Codex、复杂从句、反讽、同帖混合动作、作者编辑和删除等无法完全自动解决。编辑被暂停后，需要人工核对；尚无人工审核界面。
4. **事件归并是启发式。** 多个广泛开放事件会暂停自动选择；小范围不同帖可能是同一事故的重复说明，目前按 post ID 提醒，不能承诺事故级严格去重。
5. **去重仅限共享状态库。** 本地与云端分别开关，不具备分布式账本。相同名单只应启用一个发信端；另一端只采集/生成草稿。
6. **优先避免重复，可能漏发。** 超时、终止或 checkpoint 失败时保留 creating/created/scheduling/needs-review，不自动重新发送。先在邮件后台按 campaign ID 核查，不能清空数据库“修复”。已发出的邮件不能撤回；晚到取消公告只停止后续提醒。
7. **配额和投递不是原子保证。** 名单、其他确认邮件、额度可能在检查后变化；Brevo 受理不等于送达。没有实时退信 webhook 或自动对账任务。查看服务后台投递与退订记录。
8. **邀请码是本地入口门槛。** TOKENEMAIL 可从开源代码/客户端获知，公开订阅表单可转发；没有每码限额、有效期或服务端强验证。开放表单也缺少项目自己的速率限制，确认邮件可能被滥用消耗额度。真正的邀请制度需要可信后端。
9. **调度非实时。** 电脑退出、休眠或网络不通会漏过窗口；Github schedule 可延迟或丢弃，公共仓库长期无活动可能禁用。见 [GitHub 官方 schedule 说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。
10. **平台覆盖不完整。** 本次构建与启动检查针对 macOS arm64；Windows 缺少同等菜单栏、邀请码与系统通知集成，也未实机编译。GitHub 生产部署尚未验收。

## 如何验证真正的概率

先定义预测对象：在预测产生后的 24h 或 48h 内，是否发生指定套餐范围的额外额度重置。全体、全付费、某套餐、补偿赠送应分别标注，不能混为成功。计划公告与实际完成不是同一个结果。结果未知应保留未知，不能因为镜像没读到完成就标为失败。

建立按独立事件组织的带时间数据集：保存原帖、首次采集时间、当时可见的证据、首次达到门槛的时间、后续完成证据、截止和范围。只有截止前当时已知的内容可进入预测；按时间划分开发/校准/最终检验集，不能将同一事件的不同推文拆进训练和测试，也不能用完成公告反推当初概率。

首先报告事件级误报、漏报、提醒精确率、召回率、检测延迟以及采集覆盖率。若未来引入概率模型，再用独立数据画可靠性曲线，检查预测概率与实际发生频率是否对应，并报告样本数、不确定区间、Brier score/log loss。概率校准与普通分类正确率并非同一个指标。方法参考 [scikit-learn 概率校准文档](https://scikit-learn.org/stable/modules/calibration.html)。

在独立样本不足之前，继续展示“信号评分”，不展示历史命中率或成功概率。将规则调到手写用例全部通过，只能证明这些回归条件，不证明真实世界准确率。
